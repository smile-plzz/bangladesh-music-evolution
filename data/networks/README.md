# Bangladesh Music Preference Network (BMPN)

Graph data connecting artists, genres, concerts, and (eventually) listener communities.

## Status: Prototype

`bmpn-prototype.json` is auto-generated by `analysis/scripts/build_bmpn_prototype.py` from concert co-billing data (`data/concerts/*.json`). It is a **first-pass proxy**, not a validated preference network:

- **Nodes**: all 24 catalogued artists (`data/artists/`)
- **Edges**: pairs of artists who shared a concert bill, weighted by number of shared events, with `shared_events` listing the underlying concert IDs
- **Coverage gap**: with only 8 seed concert entries, most nodes (19 of 26 — note this count also picks up entities incidentally referenced as `artist_id` in concert data) are currently isolated (no edges). This will improve as the concert database (`data/concerts/`) grows toward its ≥500-event target.

## Regenerating

```
python3 analysis/scripts/build_bmpn_prototype.py
```

Re-run after adding new concert or artist records; the script is idempotent and overwrites `bmpn-prototype.json`.

## Planned Extensions

1. **Streaming/playlist co-occurrence** — related-artist and playlist-adjacency signals from Spotify/YouTube (pending public data collection; see `docs/roadmap.md`).
2. **Social listening / community discussion** — shared-fandom signals from social media sampling.
3. **Community detection** — once the graph has sufficient density, apply standard algorithms (e.g., Louvain) to identify listener-ecosystem clusters, feeding into the BMEM's "Listener Preference Networks" dimension.
4. **Genre-weighted edges** — distinguish co-billing within a single genre scene (e.g., the metal-scene cluster already visible: Artcell–Warfaze–Cryptic Fate–Mechanix) from cross-genre pairings (e.g., the Coke Studio Bangla folk-hip-hop pairing).
