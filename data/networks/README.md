# Bangladesh Music Preference Network (BMPN)

Graph data connecting the catalogued artists. Everything here is generated by
`analysis/scripts/`; do not hand-edit.

## A naming caveat, stated first

These files are called the *preference* network for continuity with the project
proposal, but that is not what the edges record. They record **co-appearance**:
shared concert bills, shared members, and one act naming another as an
influence. None of that is audience-side evidence. The classic mainstream-rock
community exists because Ayub Bachchu played in Souls, LRB and Nagar Baul; Lalon
Band and Chirkutt are highly central because festival programmers put a folk act
on nearly every bill. A genuine preference network needs playlist co-occurrence
or related-artist adjacency, which is blocked pending API credentials
(`docs/roadmap.md`). See `frameworks/bmem-validation.md`, Dimension 4.

## Files

| File | Contents |
|---|---|
| `bmpn-multilayer.json` | The full graph: 63 nodes, 179 edges, four layers, per-edge provenance |
| `bmpn-prototype.json` | Co-billing layer only, in the original format the web frontend reads |
| `bmpn-communities.json` | Louvain communities for the observed and full passes |
| `bmpn-clusters.json` | Connected components over co-billing — a coverage diagnostic, superseded for community detection |
| `influence-network.json` | Bipartite: acts and the global influences they cite, plus domestic transmission edges |

## Edge layers

| Layer | Edges | Evidence | Observational? |
|---|---:|---|---|
| `co_billing` | 133 | A documented shared concert bill | yes |
| `personnel` | 15 | A shared named member | yes |
| `domestic_influence` | 6 | One catalogued act names another as an influence | yes |
| `influence_homophily` | 36 | Two acts cite the same named global influence | **no — inferred** |

`influence_homophily` proxies aesthetic proximity, not shared audience. It is
flagged on every edge it produces, weighted at half, and excluded from the
headline `observed` pass.

**Co-billing edges carry two weights.** `weight` is the raw count of shared
bills; `normalised_weight` divides each event's contribution by (n−1) so an act
contributes a total of 1 per event regardless of bill size. The normalised one
feeds `combined_weight` and all analysis. Without it, the 2020 Joy Bangla
Concert's twelve-act bill alone contributes 66 edges and observed modularity
falls from 0.428 to 0.159 — both figures come from the same pipeline run, as
the `observed` and `observed_uncorrected` passes.

## Current structure

| Pass | Edges | Density | Largest component | Isolated | Modularity | Communities ≥3 |
|---|---:|---:|---:|---:|---:|---:|
| observed | 153 | 0.078 | 36 | 20 | 0.428 | 6 |
| full | 179 | 0.092 | 41 | 18 | 0.425 | 5 |
| co-billing only | 133 | 0.068 | 24 | 39 | 0.182 | 3 |

35 of 63 acts have no documented event. Low centrality in this graph is usually
a coverage fact, not a finding — Meghdol holds degree 8 and betweenness 0
because its live history before 2023 is not in the dataset.

## Regenerating

```bash
python3 analysis/scripts/build_bmpn.py
python3 analysis/scripts/analyze_bmpn.py
python3 analysis/scripts/build_bmpn_clusters.py   # optional coverage diagnostic
python3 analysis/scripts/influence_analysis.py
```

All are idempotent and overwrite their outputs. Re-run after adding artist or
concert records.

## Planned extensions

1. **Streaming and playlist co-occurrence** — the layer that would make this a
   preference network. Blocked on API credentials.
2. **Social listening / shared fandom** — from public community discussion.
3. **Temporal snapshots** — the graph is currently static across 1972–2026;
   decade slices would show the network forming.
4. **Venue and organiser nodes** — currently only artists are nodes, so the
   programming effects visible in the concert typology cannot be modelled here.
